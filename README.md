# iPAS 科目三自適應練習站

以中級「機器學習技術與應用」為範圍的自學網站規劃。重點不是背答案，而是用原創變體確認理解，並依練習證據調整下一步。

> **目前狀態：需求與設計草案，尚未實作或部署網站。** 下列功能、測試與驗收均為待完成規格，不代表已通過。這不是官方網站，也不提供正式考試分數或通過機率保證。

## 使用者會如何使用

開啟網站 → 選擇本次可用時間 → 匯入舊報告或做短診斷 → 閱讀必要的小節 → 回答未見變體 → 檢查解析 → 看下一次的練習安排。

每個建議都應說明原因，例如「同一指標的計算已答對，但換成程式後仍有困難，因此下一組練習改成逐步讀碼」。使用者可以略過、降低難度或自行選章節。

## 提議的第一版預設

- 繁體中文，桌機與手機可用，學習者不必註冊或登入。
- 公開程式與經審查的原創題；個人作答、成績、筆記預設只留在自己的瀏覽器。
- 不依賴付費 AI API。動態調整由可解釋、可測試的規則完成。
- 先以匯出／匯入備份換機；自動跨裝置同步是另行確認的選用功能。
- 圖片、公式渲染資源與程式碼隨網站版本打包，不依賴第三方題庫圖片網址。
- 不將使用者提供的官方 PDF、完整題庫或個人報告直接提交至公開儲存庫。來源資料與公開內容分開處理。

## 不是「AI 每答一題就亂生新題」

第一版擬採 **審查過的原創題庫 + 受限制的變體 + 本機選題規則**。題目數量與可用變體有限；不足時明確顯示不足，不把重複題偽裝成未見題。

學習適應、變體製作、AI 對話是三個不同能力。即使沒有 AI API，前兩者仍可運作。新題要經過內容與技術審查才可進入計分題庫。

演算法只產生學習優先順序與證據標記，不產生未经校準的能力百分比或「正式考試通過率」。詳細規格見 `docs/ADAPTIVE_LEARNING.md`。

## 圖片與程式題是發布前提，不是美化項目

- 必要圖片未打包、無法解碼或與題目版本不一致：阻止該題發布。
- 執行時圖片失敗：優先恢復同版本資產；否則暫停該題，標示無效，不扣分、不更新能力。
- 只對看起來正常的首頁截圖不夠；每個啟用的圖片／程式題都必須有驗證紀錄。
- 程式題使用真正的文字來源，不只貼程式截圖。可執行題在固定環境驗證答案；故意有錯的程式另外標示預期錯誤。
- 模考若有無效題，保留有效題統計，但整回不列入達標證據，不能用縮小分母美化成績。
- 交卷採頁面內確認；重複點擊、彈窗被封鎖、儲存失敗皆須有可恢復行為。

詳細測試契約見 `docs/QUALITY_GATES.md`。

## 技術方向：待確認的建議，不是已部署架構

- 前端：TypeScript + React + Vite，將題目、評分、選題、保存與畫面分離。
- 瀏覽器資料：IndexedDB；獨立備份匯出／匯入，不承諾本機保存永不丟失。
- 發布：GitHub Pages，使用專案路徑 `/iPASS_AI_exams/`；不可假設部署在網域根目錄。
- 題目：結構化資料，穩定 ID、版本、選項 ID、題族 ID、來源、資產清單與審查狀態。
- 品質：單元測試、Python 題目參照測試、Playwright 畫面／操作／網路故障測試；全部通過後才准許發布。
- 即時 Python、雲端同步與 AI API 不列為第一版必要依賴。GitHub Pages 本身是靜態網站服務，不是 Python 後端。

公開靜態題庫的答案可由原始碼取得，因此定位為誠實自測，不宣稱防作弊或保密測驗。新題驗收以學習流程未揭露過的題目為準，不代表技術上不可檢視。

## 實作順序

### M1：先確保能放心做題

完成題目／來源格式、基礎閱讀與作答、原創變體小批次、圖片與程式驗證、可靠交卷、保存恢復和基本部署。先驗證完整流程，不用大量未審核題目充數。

### M2：加入個人化閉環

完成技能與錯因模型、先備關係、可解釋選題、間隔複測、每日安排、證據儀表板、獨立模考保留池。全科覆蓋與個人弱項要同時考慮。

### M3：經需要再擴充

離線包、受限制的瀏覽器程式實驗、AI 助教、跨裝置同步。各項先確認必要性、隱私、維護成本與失敗模式。
