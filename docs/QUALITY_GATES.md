# 內容、图片、程式題與作答可靠性

> 狀態：待實作的驗收契約。本文件不是測試執行報告，也不表示目前已有可部署的網站。不承諾永遠沒有故障；要求的是能預防、偵測、隔離並恢復，不能讓故障變成使用者的錯題。

## 1. 先分清四種資料

| 類別 | 保存原則 | 是否進公開題庫 |
| --- | --- | --- |
| 官方來源 | 保存檔名、版本、頁碼／題號、來源雜湊與閱讀狀態；不靜默改寫 | 原始 PDF 與整份原題不預設公開 |
| 官方勘誤 | 指向原始位置，分列更正前與更正後 | 只發布必要的定位與教學說明 |
| 工程查核／教學補充 | 與官方內容分開，附依據及適用版本；有疑義時明示 | 審查後才發布 |
| 原創變體 | 使用新的情境、資料、推理任務與素材；保留來源考點關聯 | 通過內容及技術審查後發布 |

來源順序是本專案採用的整理規則，不假定所有來源彼此一致。遇到相互矛盾的敘述或疑似錯誤，標記待核對；不把外部常識混進「官方原文」，也不把原公布答案悄悄換掉。

已核對的例子：1150410 勘誤表 PDF 第 7 頁，把科目三指引印刷頁 5-21 的 Recall 分母由 TP+FP 更正為 TP+FN。此定位可作為更正流程測試，但不能由此推定全書其他內容均已審查。

## 2. 題目結構與發布狀態

每題應包含穩定 ID、內容版本、題族／模板、細考點、任務型態、題幹、選項 ID、答案 ID、逐選項解析、来源定位、必要素材清單、程式環境／測試資訊，以及審查紀錄。

狀態至少為 `draft`、`needs_review`、`verified`、`quarantined`、`retired`。只有 `verified` 能出現在計分題庫。

### 發布前阻擋條件

- 單選題不是恰好一個有效正解，或出現等價的重複正確選項。
- 題目條件不足，讓多種答案都合理。
- 結果需要的四捨五入、分母定義、正類、矩陣方向、資料型別或環境沒有說清楚。
- 題幹、圖表、程式碼、參考輸出、答案、解析不屬於同一版本。
- 改過題文或程式，但驗證紀錄的內容雜湊仍是舊版。
- 宣稱來自某一頁／題，但未確認該頁或完整跨頁題組。
- 缺少圖片或程式內容，只剩「如上圖」等指示。
- 變體實際上只是換人名、換選項順序，卻標為新推理題族。

選項順序由畫面呈現決定，但答案只能綁穩定 ID。包含「A 與 C」等選項互引的題目要禁止任意重排，或改用穩定敘述標籤並在測試中驗證對應；不能只重排畫面字母。

## 3. 圖片不丟失的完整流程

### 3.1 來源解析不能只抓文字

已核對的 115 年第一次試卷 PDF 第 11 頁，第 40、41 題的程式以圖片呈現；第 14 頁另有題組程式與候選程式。純文字解析可能只留下題幹和「下圖」。114 年第二次試卷第 17 頁同樣有程式圖片與資料表。

因此來源檢查須包含實際頁面圖片。題組跨頁時把共用題幹、圖表、程式、選項和續頁關聯一起核對。沒有讀到的內容不能靠猜測填補。

原創題以可編輯文字、結構化資料表或自製圖表為主；需要保留來源圖片做核對時，與公開素材分開存放，不將整頁原題含答案欄直接送給作答者。

### 3.2 所有必要素材隨版本打包

- 不熱連結第三方題庫、暫存下載網址或有登入要求的圖片。
- 每個必要素材記錄 asset_id、相對路徑、SHA-256、格式、寬高、題目版本、用途、文字說明、來源／權利狀態。
- 發布時驗證真實檔案存在、可解碼、尺寸足夠；成功回應但內容是錯誤頁不算圖片有效。
- SVG 必須可解析並排除脚本、外部引用及不受控內容。SVG 內的字型、圖標、嵌入圖片也要檢查，不只查最外層檔案。
- 使用部署基底路徑處理圖片、腳本和樣式。在 `/iPASS_AI_exams/` 測試，不只在根目錄 `/` 測試。
- 由結構化數據產生的圖表，題目、數據、圖表和答案一同更版。數據正確不代表圖一定正確，仍須核對座標軸、圖例、標籤、截斷與比例。

### 3.3 呈現與故障行為

桌機和手機皆提供放大、必要的平移／捲動，以及不洩漏答案的文字描述。能以資料表等價表達時提供資料表；不能等價表達的視覺題，不用一段模糊替代文字假装可作答。

必要素材進入 `loading` 時該題不啟動有效作答計時；確認載入且可讀後才開放作答。載入失敗時顯示明確訊息、有限次重試及「回報／稍後重試」，不是無限轉圈。

恢復只能使用相同版本、相同雜湊的快取。仍失敗時將題目標為 `technical_invalid`，保存已做的選擇但不計對錯、不更新學習能力。日常練習可在使用者同意後換等考點題；固定模考不在進行中偷換題。

有無效題的模考可以顯示有效題答對數及問題清單，但整回不列入達標證據。不能偷偷減少分母，產生看似合格的成績。

### 3.4 圖片必測案例

1. 正常載入、桌機和手機放大均可讀。
2. 必要圖片 404、403、逾時、零位元組、解碼失敗。
3. 同一路徑回傳舊版本圖片或 HTML 錯誤頁。
4. 正確圖檔但縮成看不清數字；標籤被裁切或顏色對比不足。
5. GitHub Pages 專案子路徑載入與內頁重新整理。
6. 快取有圖但題目版本不同；不能混用。
7. 必要圖載入失敗後交卷、重整與匯出，仍維持無效狀態。

## 4. 程式題：畫面對，答案也必須對

### 4.1 程式文字是唯一正式來源

使用 UTF-8 程式文字，畫面以 `<pre><code>` 或等價元件呈現。顯示、複製與參考測試共用同一份程式來源；行號、語法著色與題目標記不得混進複製內容。

保留縮排、換行與 ASCII 運算符。題目特意使用非 ASCII 內容時可保留，但要審查字元混淆。測試 `<=`、`>=`、`<`、`>`、`&`、引號、反斜線、切片冒號、負號與空白，不讓 HTML 或 Markdown 把它們改寫。

程式、筆記和匯入內容不可直接當作 HTML 執行；匯入備份只接受限定格式的資料，不接受任意脚本。手機橫向捲動或軟換行只影響視覺，不改動原始碼與複製結果。

### 4.2 程式題分類後驗證

| 類型 | 驗證方式 |
| --- | --- |
| 可執行、問輸出 | 在指定環境執行同一份程式，核對標準輸出及中間資料 |
| 故意有錯、問原因 | 驗證預期錯誤／錯誤狀態存在，不因執行失敗就自動刪題 |
| 最小修正 | 驗證原程式的問題、正確選項修復，以及其他選項在題設下为何不成立 |
| 填空片段 | 驗證正確填入後的完整程式；不把占位符片段冒充直接可執行檔 |
| 架構／流程概念 | 核對版本相符的 API 語意及適用条件，使用小型實驗補證；標示不是精確輸出題 |
| 圖表或訓練結果判讀 | 保存固定輸入／輸出與生成程序，另核對圖表；不要求隨機訓練每次剛好同分數 |

### 4.3 固定環境及數值契約

記錄 Python、NumPy、pandas、scikit-learn、PyTorch 等實際用到的版本，採鎖檔或固定環境；不為了題目一律裝所有框架。題目使用明確的小型資料、資料型別、必要參數與本地資料集，避免執行測試時再下載外部資料。

固定種子只是必要工具之一，不代表跨版本、平台或硬體輸出一定相同。精確數值題优先用可解析、小型、確定性的計算；浮點值指定容差或格式化規則，shape、元素數量與整數結果則精確比較。不可用無意義的小數尾差當作干擾選項。

PyTorch 官方重現性說明明確指出不同版本、平台與 CPU／GPU 間不能保證完全相同結果。因此不要把隨機模型訓練後的單一準確率寫成無條件標準答案。參考：https://docs.pytorch.org/docs/stable/notes/randomness.html

### 4.4 不只驗證「能跑」

參考測試也要核對：正類定義、混淆矩陣列欄方向、整數／浮點除法、ddof、bias、batch 與 feature 維度、fit／transform 的使用範圍、交叉驗證內是否洩漏、logits 與標籤格式。這些是工程檢查項目，不能由程式成功結束推定全部正確。

變體的預期結果由獨立的數學推導、經審查的參照計算或可驗證契約產生。不能使用同一段可能有錯的產題邏輯同時產生題目與「驗證答案」，然後據此宣稱完全正確。概念唯一性與條件完整性仍須人工審查。

### 4.5 執行安全

首版作答不執行使用者任意程式。逐步狀態是經驗證的範例資料，必須標示為「預先驗證的步驟」，不冒充即時執行。

CI 只執行經審查的題庫程式，不在具敏感權限的工作中執行未知匯入檔或外部貢獻程式。採最低權限、無秘密憑證、限制網路與執行資源；需執行不可信程式時使用額外隔離環境與時間／記憶體限制。

未來加入即時 Python 實驗再評估瀏覽器執行器與套件支援範圍。重型框架不能在瀏覽器執行時，提供同版本下載範例或已驗證輸出；不放一個永遠初始化的按鈕。

## 5. 交卷、保存與恢復

### 5.1 交卷狀態機

使用 `editing → confirming → committing → submitted`，另有可恢復的 `save_failed`。確認介面是頁面內元件，不依賴原生 `window.confirm()`。

確認頁顯示未答題與未填信心數。點取消回到原作答，不清除內容。提交前擷取最新答案、理由與輔助旗標；防止文字剛輸入但尚未保存時交卷丟字。

以唯一 attempt_id 寫入同一筆首次交卷，重複點擊或重送不得重複計分、重新排程或覆寫首次結果。寫入成功後明確顯示結果並移動焦點；失敗時保留記憶體內容、顯示原因、提供備份／複製和重試。

若保存失敗但使用者選擇查看解析，必須將這次曝光與「尚未持久保存」狀態包進可匯出報告。不能假裝已安全保存，也不能把揭露答案後的重做當首次閉卷。

### 5.2 瀏覽器保存不等於備份

用 IndexedDB 保存結構化事件；命名空間包含應用程式 ID，避免同一 GitHub Pages 網域其他專案的資料名稱衝突。題目快取与個人成績分開管理，更新題庫不能清掉作答資料。

設置儲存可用性檢查、持久儲存請求的結果提示，以及可選的備份提醒。瀏覽器配額、清理與私密模式可能影響資料保留；不宣稱本機資料永不遺失。參考：https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria

備份含 schema_version、題庫版本、事件 ID 與必要校驗資訊。匯入先預覽、驗證大小和結構、去重並提供合併／取代選擇；取代前匯出舊資料。版本遷移要可失敗回復，不能遇到不相容就自動清庫。

多分頁同時作答使用版本／鎖定或衝突提示，避免後存的空白頁覆寫已完成紀錄。舊 HTML 只能透過已支援的報告匯入；新網站不能假定可以讀取不同瀏覽器來源下的舊 localStorage。

### 5.3 互動必測

全答、部分答、不會、全未答；確認／取消；連按交卷；彈窗被封鎖；IndexedDB 不可用／配額滿；交卷前後重整；恢復、重做與首次結果並存；匯出／匯入；剪貼簿或下載不可用；兩個分頁衝突；鍵盤操作、輸入法組字與手機操作。

啟動失敗時提供可讀的錯誤與診斷資訊，不能只有空白頁。JavaScript 未啟用時提供說明；載入失敗不能留下看似可用但無反應的交卷按鈕。

## 6. 發布與更新測試

提議使用 TypeScript 單元測試、程式題參照測試與 Playwright 的瀏覽器操作／畫面／網路故障測試。測試通過不是內容絕對無誤的保證，仍保留題目回報與撤回機制。

发布工作依序執行：內容結構與來源檢查 → 資產檢查 → 程式驗證 → 評分／選題／保存單元測試 → 完整建置 → 桌機與手機操作及視覺檢查 → `/iPASS_AI_exams/` 子路徑測試 → 發布 → 已部署頁面的煙霧測試。任一步失敗不能將新版標為正常發布。

Playwright 能攔截或阻斷圖片等請求，適合驗證缺圖時的實際使用者行為。路由攔截測試與 Service Worker 快取測試要分開處理，避免快取掩蓋本來想注入的網路錯誤。參考：https://playwright.dev/docs/network

每個啟用的圖片與程式題都要有完整性和呈現測試覆蓋，不只截首頁。視覺基準更新必須審查差異，不能遇到測試失敗就一律接受新截图。

專案發布基底路徑按 Vite 官方部署說明設定。參考：https://vite.dev/guide/static-deploy.html

## 7. 離線與版本一致性

離線包屬後續功能。下載時檢查該包全部題目與必要素材；只在完整時標「可離線」，不能只快取首頁就宣稱全站離線。

新題庫與資產以不可變版本／雜湊識別；原子切換到完整版本。測驗進行中保留原版本，不強制熱更新；更新失敗可留在舊的完整版本。快取淘汰與恢復都不能任意刪除個人事件。

## 8. 公開儲存庫與回報隱私

公開內容僅包含應用程式、原創已審查題目、必要的原創素材與來源定位。官方 PDF、使用者真實分數、自由文字筆記、API 金鑰、個人備份不自動提交。

錯誤回報預設只包含應用程式版本、題目 ID／版本、錯誤類型與使用者主動選擇的技術資訊。送出前顯示預覽，不將完整作答或檔案直接寫成公開 Issue。未登入 GitHub 的學習者仍可匯出不含個資的回報文字。

GitHub Pages 是靜態網站服務；網站需要自動跨裝置同步或代管 AI 秘密金鑰時，須另設適當的後端與同意流程。不要把公開 repository 當作成績資料庫，也不在前端提供具倉庫寫入權限的 Token。參考：https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

## 9. 最低驗收門檻

- 所有已發布題目有唯一、可追溯的版本與審查狀態。
- 所有必要素材均可解碼、在指定部署路徑可取得，手機上不丟失關鍵資訊。
- 所有可執行計分程式題通過相應環境的參照測試；其他題型有相符的審查契約。
- 故意缺圖與儲存失敗時可恢復，且不產生假的錯題、掌握度或達標證據。
- 第一次交卷、重做、備份匯入及版本更新保持可重建的歷史，不覆寫首次紀錄。
- 具體測試結果、未支援環境及尚未完成事項要寫進發布紀錄。

若程式或內容後來發現錯誤：隔離受影響版本、發布更正原因、通知使用者重算有效統計，保留原始歷史與更正紀錄；不能靜默換答案後責怪學習者。
